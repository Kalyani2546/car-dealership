# API commands and assignment evidence

Run the backend and create sample data first:

```powershell
cd server
python manage.py migrate
python manage.py seed_dealerships
python manage.py runserver
```

Use `curl.exe` in Windows PowerShell (rather than PowerShell's `curl` alias). These examples assume the default local server at port 8000. Dealer IDs are generated by your database; get one from the dealer list before using detail/review commands.

## Public GET requests

```powershell
curl.exe -i http://127.0.0.1:8000/api/dealers/
curl.exe -i http://127.0.0.1:8000/api/dealers/?state=KS
curl.exe -i http://127.0.0.1:8000/api/dealers/1/
curl.exe -i http://127.0.0.1:8000/api/dealers/1/reviews/
curl.exe -i http://127.0.0.1:8000/api/cars/
```

Use the Kansas-filtered command for `getdealersbyState`, the all-dealers command for `getalldealers`, the selected dealer command for `getdealerbyid`, and the reviews command for `getdealerreviews`. Substitute an ID returned by your local database.

## Sentiment analysis

```powershell
curl.exe -i -X POST http://127.0.0.1:8000/api/analyze-review/ -H "Content-Type: application/json" --data-raw '{"review":"Fantastic services"}'
```

Save the actual command and response as `analyzereview`. The project returns JSON with a positive label and score for this phrase.

## Registration, login, logout, and review submission

The API uses Django session authentication and CSRF protection. For each new PowerShell terminal session, first get a CSRF cookie and preserve it in a cookie jar:

```powershell
curl.exe -c cookies.txt -b cookies.txt http://127.0.0.1:8000/api/csrf/
```

Register an account using unique values; registration signs that account in:

```powershell
curl.exe -i -c cookies.txt -b cookies.txt -X POST http://127.0.0.1:8000/api/register/ -H "Content-Type: application/json" -H "X-CSRFToken: <csrftoken-from-cookies.txt>" --data-raw '{"username":"your-unique-username","first_name":"Your","last_name":"Name","email":"you@example.com","password":"use-a-unique-strong-password"}'
```

Read the `csrftoken` value from `cookies.txt` and replace the placeholder. Save your real credentials securely; never commit them. Login and registration rotate the CSRF token, so fetch `/api/csrf/` again and use the latest token before each subsequent POST. Keep passing the same `-c cookies.txt -b cookies.txt` arguments:

```powershell
curl.exe -i -c cookies.txt -b cookies.txt -X POST http://127.0.0.1:8000/api/login/ -H "Content-Type: application/json" -H "X-CSRFToken: <csrftoken-from-cookies.txt>" --data-raw '{"username":"your-unique-username","password":"your-password"}'
curl.exe -i -c cookies.txt -b cookies.txt -X POST http://127.0.0.1:8000/api/logout/ -H "X-CSRFToken: <csrftoken-from-cookies.txt>"
```

Capture the real login and logout command/response in `loginuser` and `logoutuser`. To submit a review, log in again and use a valid dealer ID:

```powershell
curl.exe -i -c cookies.txt -b cookies.txt -X POST http://127.0.0.1:8000/api/reviews/ -H "Content-Type: application/json" -H "X-CSRFToken: <csrftoken-from-cookies.txt>" --data-raw '{"dealer_id":1,"rating":5,"review":"Fantastic services"}'
```

## Evidence that must be captured from your environment

- Save runserver startup output as `django_server`; save an actual successful GitHub Actions run's logs as `CICD`.
- Create an admin user yourself with `python manage.py createsuperuser`; take the requested login and logout screenshots in your browser.
- Take screenshots of the local pages only after opening them in the browser and completing the relevant interactions. Use the exact filenames from the assignment.
- `deploymentURL`, deployed screenshots, public GitHub file URLs, and public workflow logs require your own GitHub and IBM Cloud accounts; they cannot be truthfully produced from this local starter workspace.
